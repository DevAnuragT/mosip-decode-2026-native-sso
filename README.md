# Native SSO in eSignet (Go) for Mobile Apps

**MOSIP Decode 2026 · Problem statement 03 · eSignet | Enable Native SSO in eSignet Go for Mobile Apps**

One login in a vendor's first native app; silent, cryptographically bound sign-in in every other app
of that vendor on the same device. Implemented as **OpenID Connect Native SSO for Mobile Apps 1.0** on
eSignet (Go) and the ThunderID engine, with two Android reference apps, an automated end-to-end
test, a Postman collection and full documentation.

```
 Vendor Wallet (super app)                    eSignet (Go) + ThunderID                  Vendor Health (child app)
 ───────────────────────────                  ────────────────────────                  ─────────────────────────
 PAR + PKCE + DPoP (Key A)  ───────────────▶  OTP login, consent
 token (authorization_code) ───────────────▶  device_sso ⇒ device_secret (JWE) + id_token{ds_hash, sid}
 store id_token + device_secret
                            ◀── IPC (signature permission): id_token, device_secret, DPoP proof by Key A ──
                                              token exchange ◀───────────────────────────  subject=id_token, actor=device_secret
                                              ds_hash · sid · cnf.jkt · sub · vendor · scope ⊆ grant · consent
                                              access_token{cnf.jkt=Key A, act.sub=Wallet} ──▶  userinfo (DPoP by Key A)
```

## What is in this repository

| Path | What |
|---|---|
| `repos/thunderid` (git submodule-style checkout of [thunder-id/thunderid](https://github.com/thunder-id/thunderid), branch `feature/ps03-native-sso`) | Engine side: `device_sso` scope, `DeviceSecretProvider` + `DeviceSSOConsentProvider` interfaces, device-secret issuance on the authorization-code grant, RFC 8693 token exchange with `actor_token_type=device-secret`, all bindings and scope rules, attribute caching for the exchanged token. 20+ unit tests. |
| `repos/esignet-go` (checkout of [mosip/esignet](https://github.com/mosip/esignet) `develop-go`, branch `feature/ps03-native-sso`) | eSignet side: `DeviceSecretProvider` (signed-then-encrypted device secrets through the keymanager), vendor-family isolation, derived consent with audit trail, `token_exchange` client registration, config, OpenAPI and design docs. 30+ unit tests. |
| `mobile-sample/` | Android: `nativesso-sdk` library + **Vendor Wallet** (super app) + **Vendor Health** (child app), signed with one vendor certificate. |
| `tests/native_sso_e2e.py` | Laptop-side end-to-end test of the whole protocol against a running eSignet: 26 checks incl. all negative cases. Results in `tests/results/`. |
| `postman/` | Postman collection + local environment (generated by `postman/build_collection.py`). |
| `docs/` | Submission documents: design document, API documentation, test cases and results, demo video script, pitch deck. |
| `ui-theme/` | Modern minimal restyle of the eSignet login screens (server theme + mounted stylesheet, no UI rebuild). |

## Run the whole thing locally

```bash
# 1. Infrastructure (PostgreSQL + mock identity system)
cd repos/esignet-go/docker-compose && docker compose -f dependent-docker-compose.yaml up -d

# 2. eSignet from source (developer mode; .env is prepared, see docs/configuration.md)
cd ../esignet-service && ./make.sh run            # http://localhost:8088

# 3. Login UI (container) with the modern theme, proxying to the host eSignet
#    (set MOSIP_ESIGNET_THEME_ID=theme-modern in esignet-service/.env and copy ui-theme/theme-modern.yaml
#     into esignet-service/data/themes/ first)
"$REPO_ROOT"/ui-theme/run-ui.sh

# 4. Register the demo clients (generates the apps' client keys)
cd "$REPO_ROOT" && python3 mobile-sample/scripts/register_clients.py

# 5. Prove the backend end to end (no phone needed)
python3 tests/native_sso_e2e.py        # 26/26 checks

# 6. Build + install the apps (see mobile-sample/README.md)
```

Test identity (seeded by `init.sql`): UIN `1774231323`, OTP `111111`, hCaptcha test key.
